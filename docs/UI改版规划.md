# 3S UI 改版规划：黑白极简风格（对标参考图）

> 目标：全系统从当前的「墨绿主题」切换为与 3S 线下门店一致的**白底黑字**极简风格，视觉对标 `参考图/` 文件夹（M Stand 小程序）。
> 范围：移动端 H5（会员端 + 员工端）、商户管理后台、平台总后台、门户页。

---

## 一、参考图风格拆解

颜色均从 `参考图/` 10 张截图按像素取样，不是凭感觉估的。

| 特征 | 参考图做法 |
|---|---|
| 色彩 | 只有黑、白、灰三类颜色，**没有任何品牌彩色**。黑色是唯一的强调色 |
| 背景 | 页面底色是极浅灰，内容卡片纯白，两者靠明度差区分，**基本不用阴影** |
| 主按钮 | 纯黑底、白字、全圆角胶囊（「立即兑换」「手机号快捷登录」「充值」「兑换」） |
| 次按钮 | 白底黑字细描边胶囊（「提醒我」） |
| 分段切换 | 选中项：黑底白字方块；未选中：浅灰底、浅灰字（「咖啡产品 / 潮流周边」） |
| 侧边分类 | 选中项白底 + 粗黑字 + **左侧黑色竖条**；未选中浅灰底灰字 |
| 底部导航 | 悬浮的白色大圆角胶囊，图标是细线条；选中项黑色，未选中浅灰 |
| 标题 | 粗黑中文标题（参考图常配小号英文副标题，**本项目不采用**） |
| 卡片 | 大圆角（约 12–16px）、纯白、留白充足 |
| 标签 | 黑底白字小方块（「周一美式 一周没事」「套餐价 ¥46」）或浅灰底小字 |
| 分隔 | 很淡的细线，或者只靠留白 |
| 浮层提示 | 黑色胶囊（「加入『场』牌会员赠新人好礼券」） |
| 图标 | 细线条风格（1.5px 左右），单色 |

### 功能色（已确认）

参考图是纯商城页面，没有「已确认 / 已取消 / 已爽约 / 欠款 / 退卡」这类业务状态。健身房系统必须让员工一眼分清状态，所以建议**只保留一个低饱和红色**表达风险：

| Token | 色值 | 用途 |
|---|---|---|
| `--c-danger` | `#D23C3C` | 爽约、欠款、退卡、删除、下降趋势 |

其余状态全部用黑白灰的「填充 / 描边 / 灰底」三种形态区分：

| 状态 | 表现 |
|---|---|
| 已确认 / 使用中 / 已核销 | 黑底白字 |
| 待确认 / 待学员确认 / 待开卡 | 白底黑字黑描边 |
| 已取消 / 已过期 / 已停用 | 浅灰底灰字 |
| 已爽约 / 已退卡 / 欠款 | 红字红描边 |

## 四、技术实施方案

现状盘点（`server/web` 下）：

- 品牌绿 `#0d5e56` 在 JS 模板和 CSS 里**写死了 289 处**，分布在 52 个文件里，最多的是 `staff-coach.js`、`app.css`、`staff-finance.js`、`staff-courses.js`。
- 其他写死的颜色还有几十种（`#c98a2d` 金黄、`#4338ca` 靛蓝、`#ee0a24` 红等）。
- 已经有 CSS 变量体系（移动端 `--brand`、后台 `--el-color-primary` 等），但只有一小部分代码在用。

所以改版分两步：**先把颜色收拢到变量，再换变量的值**。这样以后要调色只改一个文件。

### 阶段 1：建立 Token，清理写死的颜色（不改视觉）

- 在三端 `app.css` 的 `:root` 里定义第二节的全部 Token。
- 把 289 处 `#0d5e56` 和其它写死颜色替换成 `var(--…)`，包括 ECharts 配置里的颜色。
- 这一步完成后页面外观不变，方便单独验证没有改坏东西。

### 阶段 2：移动端 H5 换肤（优先，会员和教练每天在用）

1. 改 Token 的值为黑白灰，同步 Vant 的主题变量（`--van-primary-color` 等）。
2. 主按钮、次按钮、Tabs、标签、Toast、弹层按第三节改。
3. 会员端底部导航改成悬浮胶囊样式。
4. 状态字典 `DICT` 的颜色映射改成四种形态。
5. 首页、我的、约课、私教、卡包这几个会员高频页逐页过一遍细节。
6. 员工端工作台、预约管理、课表、报表逐页过一遍。

### 阶段 3：商户管理后台 + 平台总后台

1. Element Plus 主题变量 `--el-color-primary` 整套换成黑色系。
2. 侧边栏改白底黑字。
3. 数据看板图表改灰阶。
4. 现有深色主题（`html.dark`）同步改成「黑底白字」对应版本。

### 阶段 4：门户页、登录页、小程序壳

- 登录页参考第 10 张图：大 Logo + 欢迎语 + 黑色大胶囊按钮。
- 门户页、小程序壳统一配色。

### 每个阶段的交付方式

- 每个阶段单独提交推送，单独给部署提示词，你可以一阶段一上线。
- 每个阶段我会用浏览器在本地截图（移动端按手机尺寸），把改版前后对比图发给你确认后再进下一阶段。

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| 去掉彩色后状态不好区分 | 用「黑填充 / 描边 / 灰底 / 红」四种形态，并保留状态文字 |
| 图表系列多时灰阶难分辨 | 单图最多 5 个灰阶；系列再多的改成排行条形图 |
| 写死颜色漏改，页面出现残留绿色 | 用 `server/scripts/check-colors.js` 每阶段扫描，第 3 阶段结束时残留必须为 0 |
| 浏览器缓存导致新旧样式混杂 | 服务端已有启动版本号机制，部署后自动刷新资源 |
| 员工已习惯绿色界面 | 布局和操作位置不变，只换视觉 |

## 六、已确认的决定（2026-10-26）

1. **功能色**：只保留偏暗红 `#D23C3C` 表达风险状态（爽约、欠款、退卡、删除、下降），其余状态用黑底、黑框、灰底区分。
2. **英文副标题**：不加，页面标题保持纯中文。
3. **Logo**：由你提供黑色版 3S Logo，放到 `server/web/static/` 后在第 2 阶段替换。
4. **改版顺序**：移动端 → 管理后台 → 平台后台 → 门户，一阶段一上线。
5. **后台深色模式**：保留，改成黑底白字版本。

## 七、进度

### 第 1 阶段（已完成）

- 新增 `server/web/static/theme.css`：全站配色变量的唯一来源，移动端、管理后台、门户页、按钮配置页都先引入它。当前色值仍是改版前的墨绿主题。
- 品牌绿 `#0d5e56` 从 289 处写死降到 1 处（`m/index.html` 的浏览器顶栏色 `theme-color`，这个属性不支持变量，切换配色时手动同步）。
- 功能色（红、橙、涨跌、金额、金色、星星）和移动端主要灰色已全部换成变量。
- 不能用 CSS 变量的地方改为运行时读取变量：ECharts 图表、canvas 训练计划海报、二维码用 `H.color('--xxx')`（移动端）/ `themeColor('--xxx')`（后台）；SVG 图标颜色从 `fill`/`stroke` 属性移到 `style` 里。
- 新增检查脚本 `node server/scripts/check-colors.js`：统计还剩多少写死的颜色，`--list` 列出具体位置。全站写死颜色从 1038 处降到 342 处。
- 剩下的 342 处是装饰色（首页轮播深色渐变、会员卡封面渐变、AI 输入框紫色、提示条黄色等）和平台后台的靛蓝主题。这些在第 2、3 阶段重做对应组件时直接替换，第 3 阶段结束时目标为 0。
- 验证：本地起完整服务，截取移动端、后台、门户共 32 个页面，与改造前逐像素对比，除图表入场动画帧外差异均低于 0.15%，外观无变化。

### 第 2 阶段：移动端 H5（已完成）

- `theme.css` 色值切换为黑白灰（第二节色板），新增深灰档 `--c-ink-1~3`、暖灰 `--c-cream`。管理后台、门户页、按钮配置页在 `theme.css` 之后引入 `static/theme-legacy.css`（旧墨绿色值），保持原样，各自改版后删除引用。
- Vant 组件主题变量统一桥接到配色变量（主色、文字、边框、标签页、底部导航、开关、角标、Toast）。
- 组件按参考图重做：
  - 顶部区域（首页、我的、工作台、教练主页、使用引导）：与页面同底色、黑字，白色卡片压在上面。
  - 按钮：全部胶囊形；主按钮黑底白字，次按钮白底黑字浅灰描边。
  - 分段切换（登录/注册、用户数据/财务数据、已有会员/新会员建档等）：选中黑块白字，未选中浅灰块灰字。
  - 底部导航：悬浮白色圆角胶囊，选中黑色，去掉选中底色块。
  - 状态标签四种形态：已确认/使用中/已完成 = 黑底白字；待确认/待开卡/待签署 = 黑框；已取消/已过期/无卡 = 灰底灰字；已爽约/已停用/已退卡/黑名单 = 红框。字典里「待开卡」「已退卡」「会员已过期」随之调整。
  - 会员卡卡面：黑→深灰四档区分卡种，失效卡浅灰；去掉装饰圆圈。
  - 首页轮播、`banner1/2.svg` 插画、卡面内嵌插画全部转灰阶；轮播按钮/标签改白色。
  - 待处理提醒条改黑底白字；数量角标改黑色；报表占比条、课表格子、教练空闲时段条改灰阶（空闲 = 黑色）。
  - 登录页：白底、居中黑色 Logo（`static/logo-black.png`，另有反白版 `logo-white.png`）、黑色胶囊按钮。
  - 卡片去阴影，靠底色区分。
- 删除移动端样式表里 33 条 `html.dark` 死代码（移动端没有深色模式开关）。
- 移动端写死颜色清零（`check-colors.js` 中 `m/` 为 0），全站剩 131 处，均在管理后台、平台后台、门户页。
- 顺带修复：会员端「完善档案」页接口地址缺少 `/member` 前缀，读取和提交资料都失败。
- 验证：本地完整服务截取手机端 54 个页面逐页检查；管理后台、门户页与第 1 阶段逐像素对比，差异只来自日期变化（「今天」高亮与当日数据），配色无变化。
